# Fixture and interoperability policy

## Corpus layers

1. **Synthetic minimal fixtures** generated from independently written byte/XML
   descriptions. Each isolates one format rule or failure.
2. **PixInsight-produced fixtures** covering real writer behavior and metadata.
3. **Acquisition-application fixtures** from at least one independent producer
   such as N.I.N.A., covering common camera metadata and compression choices.
4. **Mutation corpus** derived mechanically from redistributable fixtures for
   truncation, overflow, invalid XML, block ranges, codecs and checksums.
5. **Private local validation corpus** for files that cannot be redistributed;
   only hashes, generator identity and non-sensitive results are committed.

No fixture generated by `mmxisf` may be its sole interoperability oracle.
Expected pixel planes use non-symmetric values so row, channel, endian and
storage-order mistakes cannot cancel out.

## Required provenance

Every fixture is recorded using `docs/fixtures/manifest.schema.json` and must
include its SHA-256, origin class, generator and version, generation procedure,
redistribution status, exercised conformance rows, expected result, and whether
the original bytes may be committed.

Astronomy binaries use Git LFS. Synthetic source arrays and compact expected
metadata remain normal Git files. Private originals stay outside the repository
under a documented local path and are never uploaded automatically.

## PFI parity corpus minimum

- UInt8, UInt16, UInt32, Float32 and Float64 where a producer supports them;
- mono and RGB;
- planar and normal storage;
- little- and big-endian blocks;
- uncompressed plus all six standard codec identifiers;
- checksum pass/fail and checksum-before-decompression evidence;
- attachment and embedded blocks; generic inline properties;
- single and multiple images;
- PFI-required XISF properties and FITS keywords;
- top-down non-symmetric pixel pattern;
- truncated header/block, overflow, unsupported version and unsupported external
  resource cases.

Final corpus composition depends on what independent producers can actually
generate. Missing combinations remain `NOT_TESTED`; they are not synthesized
into interoperability claims.
