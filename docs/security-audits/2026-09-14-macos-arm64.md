# macOS arm64 development-binary dependency audit

- Audit date: 2026-09-14
- Result: **BLOCKED / UPGRADE REQUIRED**
- Scope: the current local PFI provider bundle and the dependency headers used
  by the maintained local mmxisf build
- Candidate status: unfrozen development snapshot; not a release-candidate
  audit and not publication authorization

## Audited identity

The inspected provider is
`artifacts/pfi-mmxisf-provider-macos-arm64-4b00219/bin/pfi-mmxisf-provider`,
built from PFI commit `4b002194f89072b1c6601bd2dc2eb6d15bd76620`.
Its exact size is 465,856 bytes and its SHA-256 is
`f01ef8fe5f0a1872d6e0fcd7fe74d290519766e82974274eddd5636c7dfb0559`.
The bundle manifest records five copied non-system dynamic libraries, strict
ad-hoc signature verification, and bundle-relative linkage. The generated
mmxisf binary SPDX record identifies the dependency versions below.

The development host was macOS 26.5.2 (25F84), arm64, using Apple Clang
21.0.0 and CMake 3.24.4. MacPorts reports an operating-system platform
mismatch, which independently disqualifies this host as a controlled release
environment.

## Findings and dated production floor

| Dependency | Bundled/resolved | 2026-09-14 floor | Disposition |
| --- | --- | --- | --- |
| Expat | 2.5.0 | 2.8.4 | **BLOCKED.** 2.5.0 predates multiple memory-safety and denial-of-service fixes. Expat 2.8.4 fixes four additional vulnerabilities beyond 2.8.3, including a high-severity hash-flooding weakness. |
| zlib | 1.3 | 1.3.2 | **UPGRADE REQUIRED.** The identified 2026 `untgz` issue is outside mmxisf's linked library surface, but 1.3.2 is the current release after the upstream security audit and is the conservative publication floor. |
| LZ4 | 1.9.4 | 1.10.0 | **UPGRADE REQUIRED.** Upstream publishes no GitHub security advisory for the library, but 1.10.0 is the current stable library line. This is a currency/hardening requirement, not a claim that 1.9.4 has a known reachable CVE in mmxisf. |
| Zstandard | 1.5.5 | 1.5.7 | **UPGRADE REQUIRED.** Upstream publishes no GitHub security advisory, but 1.5.7 is the current release and includes accumulated correctness fixes. This is a conservative production floor, not a claim of a known reachable CVE in the current arm64 reader path. |
| OpenSSL | 3.2.0 | 3.5.8 | **BLOCKED.** The 3.2 line reached end of public support on 2025-11-23, and 3.2.0 predates several security patch releases. The selected floor is the current patch of the supported 3.5 LTS line. |

The OpenSSL findings include code paths beyond mmxisf's EVP digest use. That
does not rescue the artifact: production distribution must not embed an
end-of-life cryptographic library, and linking a full library requires an
exact candidate review rather than a reachability guess.

## Enforced control

Configure release-candidate builds with:

```text
-DMMXISF_ENFORCE_PRODUCTION_DEPENDENCY_BASELINE=ON
```

The configure step then rejects any resolved dependency below the dated floors
above. The option stays off by default so the old local development environment
can still build diagnostic artifacts; every beta or production candidate must
enable it. A CTest contract exercises the exact floor and a rejection below
each individual floor.

The checked `vcpkg.json` pins the official Microsoft vcpkg registry to immutable
commit `a1cae005c39be7b18ba319fced856b68d7276271`. At that commit the selected
ports are Expat 2.8.4, zlib 1.3.2#2, LZ4 1.10.0, Zstandard 1.5.7, and OpenSSL
3.6.4. This provides an isolated reproducible input graph at or above every
floor without changing the host's global package installation. The OpenSSL
3.6 line is supported only until 2026-11-01, so a candidate built near or after
that date must refresh the registry baseline and move to a supported line.
The maintained `tools/run_vcpkg_macos_arm64_gate.sh` keeps this path separate
from the older system/MacPorts gate and verifies the binary SBOM, complete test
suite, installed-package consumer, arm64 viewer identity, system-only runtime
linkage, and strict deep bundle signature.

This control is deliberately dated. It proves only that a build is not older
than the 2026-09-14 floor. It does not replace a fresh official-advisory review,
binary SBOM check, library hash capture, signing/notarization, or cross-platform
test on the exact frozen candidate.

## Exit criteria

1. Rebuild all dependencies in a controlled supported environment at or above
   the dated floors.
2. Configure with production-baseline enforcement enabled and retain the
   generated exact-version binary SPDX record.
3. Run the complete local gate, Linux/macOS/Windows matrix, and long fuzz gate
   on the same frozen source commit and dependency set.
4. Recheck current official advisories immediately before publication and
   record hashes of every distributed binary.

Until all four steps pass, the current macOS provider and viewer remain local
development artifacts and the binary-vulnerability readiness gate cannot pass.
